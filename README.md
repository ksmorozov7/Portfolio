# Мои учебные и практические проекты (DWH / ETL / BI)

Привет! В этом репозитории я собираю свои проекты по работе с базами данных, автоматизации и аналитике. 

## 1. Локальная дата-платформа (sql_sandbox и .py файлы)
Здесь я развернул в Docker связку из PostgreSQL, Apache Airflow и Apache Superset, чтобы смоделировать работу реального корпоративного хранилища.

* **Автоматизация (ETL):** Написал скрипты `bank_automation.py` и `cinema_automation.py`. Airflow раз в час запускает их, генерирует случайные транзакции/просмотры кинотеатра и складывает их в базу.
* **База данных (DWH):** Интегрировал гибридную архитектуру хранилища. PostgreSQL отвечает за OLTP-слой, а ClickHouse выступает в роли колоночного OLAP-хранилища для обработки миллионов строк. Написал SQL-скрипты в DBeaver, которые собирают сырые логи в готовые витрины данных с помощью обобщенных табличных выражений (CTE), тяжелых оконных функций (накопительный итог с операторами кадрирования ROWS/RANGE BETWEEN), джойнов и обработки Nullable-полей (COALESCE).
* **Финтех & Карточный Антифрод:** Разработал аналитический сценарий расчета матрицы ошибок (Confusion Matrix: TP, FP, FN, TN). Настроил автоматический расчет профильных банковских коэффициентов эффективности антифрода: AFPR, FPR, FDR и SAR, а также оценку прямого финансового ущерба от пропущенного фрода.
.

##  2. Исследовательские ноутбуки (.ipynb файлы)
Мои работы на стыке Data Science и анализа временных рядов:
* `LSTM_prediction.ipynb` — пример прогнозирования сигналов высокочастотных инженерных данных с помощью рекуррентной нейросети.
* `python+sql.ipynb` — препрепроцессинг, очистка данных с помощью Pandas и работа с базой через Python.
* `PySpark_benchmarking.ipynb` — стресс-тестирование распределенного движка Apache Spark (PySpark) на датасетах от 10 000 000+ строк и баттл производительности против Pandas.
* `Amazon_Sentiment_Analysis.ipynb` — классический пример NLP анализа тональности неструктурированных текстовых данных (отзывов) с помощью CountVectorizer и модели LogisticRegression (точность Accuracy: 81%). Подход применим для анализа фишинга.
